DESPRO FPGA CONTEXT
===================
Purpose of this file: give an AI assistant the context of this capstone project's RTL code,
what it does, which decisions were made, and what is currently being worked on.
Last updated: 2026-11-26 (temperature, voltage and current protection complete and integrated)

SCOPE: this file covers the FPGA / RTL side only.
The MCU firmware is described in a separate file, despro_firmware_context.txt.
Do not make assumptions about the firmware from this file; for anything firmware-related, refer to that file.
MCU-facing FPGA signals (mcu_heartbeat, boot_success, shutdown_success, ...) are described here only as the
FPGA sees them (what the RTL expects on its pins), not how the MCU produces them.


1. PROJECT OVERVIEW
-------------------
- Capstone ("Despro", design project) of a college student in Indonesia.
- Product: Portable Emergency Power Unit (a portable power supply / power bank style device).
- The FPGA part implements 2 reusable IP blocks in SystemVerilog:
    1. Power-State FSM          (fsm.sv, module power_state_machine)
    2. Fault Event Engine (FEE) (fee.sv, module fault_event_engine)
  plus a top-level module that wires them together (portable_emergency_power_unit.sv)
  and, since the current refactor, sensor readers: DS18B20 temperature (ds18b20_reader.sv) and
  INA226 voltage/current (ina226_reader.sv, using the open-source i2c_master.v).
- Long-term story of the program: ODM -> FPGA validation -> reusable IP -> ASIC (tape-out).
  So the RTL should be modular, synchronous, board-independent and reusable.
- FPGA_Template_2_IP_Siap_Tapeout-1.pdf (in this folder, written in Indonesian) is a general spec.
  It is AI generated, so the student does NOT treat it as mandatory. Use it as loose guidance only.
  Useful points from it: 7 FSM states, fault list, "clear register interface", "no board dependency",
  "all logic synchronous", "single clean clock domain", "modular RTL", "readable naming".


2. HARDWARE
-----------
- FPGA board: Sipeed Tang Nano 4K (Gowin GW1NSR-LV4C, 4608 LUT4, 3456 registers, Cortex-M3 hard core).
  - 3.3V digital I/O only. NO built-in ADC.
  - Clock: 27 MHz on-board oscillator (CLK_FREQ_HZ = 27_000_000 at the top level).
- Team split: the student's task is PROGRAMMING (RTL here). The physical circuit (wiring, resistors, power,
  protection hardware) is handled by the student's teammates. Do not bring circuit/electrical details to the
  student; assume the hardware side provides what the RTL needs.
- MCU: an ESP32 does the main control of the system. Its firmware is out of scope for this file
  (see despro_firmware_context.txt).
- Sensors (decided):
  - DS18B20  -> temperature. Protocol: 1-Wire (NOT I2C). Pins: GND, DQ, VDD. Externally powered (not parasite).
  - INA226   -> bus voltage, current, power. Protocol: I2C. Has an ALERT pin (open-drain, programmable limit).
- ASSUMPTION (decided): the FPGA has its OWN DS18B20 and its OWN INA226, on its own 1-Wire line and I2C bus.
  The FPGA does NOT share sensors or buses with the MCU (the MCU uses separate sensors if it needs them).
  Reasons: 1-Wire supports only one master (collisions -> CRC errors -> false sensor_failure shutdowns);
  a shared INA226 would get conflicting config/calibration writes and I2C collisions; and sharing breaks
  the independence the FPGA exists for (section 3). The readers are written for exclusive access
  (e.g. ina226_reader rewrites config and calibration every cycle).


3. ROLE OF THE FPGA: INDEPENDENT SAFETY MONITOR ("SHADOW LOGIC")
-----------------------------------------------------------------
- "Shadow logic" is the team's informal name, not a standard term. Standard terms for the same idea:
  independent safety monitor / independent safety channel / diverse redundancy (MCU software + FPGA hardware).
- PURPOSE: make the system FAIL SAFELY.
  - The MCU (ESP32) does the main control. The FPGA does not try to keep the system running; it guarantees
    that when something fails, the system ends up in a SAFE state (power output off), not a dangerous one.
  - Why the MCU alone is not enough: no program can be proven bug-free, and an MCU can also fail from
    brownout, corrupted flash, noise, a crashed library or stuck peripheral, or a dead sensor that keeps
    reporting "normal". A hung MCU freezes its outputs in whatever state they were in; if the output is ON
    while the battery overheats or a short circuit happens, nothing turns it off. "Broken and off" is
    acceptable, "broken and still on" is not.
  - The FPGA must therefore not fail TOGETHER with the MCU: own sensors, own logic, own output, different
    technology (hardware logic vs software).
  - Honest note: commercial power banks usually get basic protection from fixed protection chips. The FPGA is
    justified here as a programmable monitor with extra features (MCU heartbeat watchdog, fault codes, retry
    limit, state machine, configurable thresholds) and by the course goal (FPGA -> reusable IP -> ASIC).
- Design principles (all RTL decisions should follow these):
  - Own inputs: the FPGA reads its own sensors directly, never sensor values from the MCU (see section 2).
  - Own decision: thresholds are parameters inside the FPGA, not settable by the MCU.
  - Output with authority: system_enable must be able to cut power by itself, not be a request the MCU acts on.
  - Permission to run: system_enable is active-high and must be actively held high; reset/dead FPGA = off.
  - Unknown = unsafe: sensor or interface failures are detected (CRC, read-back checks, timeouts) and become
    sensor_failure -> shutdown, never treated as "all OK".
  - Watch the MCU: mcu_heartbeat input, any toggle counts as "MCU alive"; no toggle for 3 s (placeholder)
    is a heartbeat timeout -> CRITICAL.
- Known gaps / candidate features (discussed, NOT implemented, NOT yet approved by the student):
  - FPGA heartbeat OUTPUT to the MCU (cross-monitoring, so a frozen FPGA is detected). Cost: 1 pin.
  - Derive battery_low / battery_critical inside the FPGA from the INA226 bus voltage instead of input pins
    (if the MCU drives those pins, battery protection depends on the MCU). Saves 2 pins.
  - Inputs that may come from the MCU (fan_failure, sensor_failure pin, communication_timeout,
    battery_low/critical) are extra information, not independent protection.
  - Optional: drop shutdown_response / warning_response / critical_response outputs (fault_code_bus already
    carries the information). Saves 3 pins.
  - Pin budget: about 27 of ~35 usable GPIO used now (after the INA226 integration); about 23-26 after the
    changes above.
  - Not recommended for this project: MCU data link for cross-checking, startup self-test of the cutoff path,
    windowed watchdog (cost pins/complexity/firmware changes).


4. CURRENT REFACTOR (WHAT WE ARE WORKING ON)
--------------------------------------------
Change of plan: "software comparator instead of hardware comparator".
- Before: each fault input of the FEE was a 1-bit signal from an external analog comparator.
- Now: the FPGA receives NUMBERS from sensors and compares them against thresholds itself.
- Approach decided:
  - No floating point. Values are fixed-width integers (raw sensor units).
  - Thresholds are written in real units (e.g. °C) as parameters and converted to sensor units with integer
    math in localparams (e.g. DS18B20: 1 LSB = 1/16 °C, so 60 °C = 60 * 16 = 960).
  - Comparison uses hysteresis (separate set and clear levels) to avoid chattering.
  - Debounce is counted in READINGS (consecutive samples over the limit), not clock cycles, because a value
    only changes when a new reading arrives. Counting clock cycles on a held register value would let a
    single bad reading trigger the fault.
  - No 2-flop synchronizer on values that come from a module on the same clock.
  - 1-Wire (DS18B20) interface written from scratch in plain RTL.
  - I2C: the student chose an existing open-source core to save time: i2c_master.v from
    github.com/alexforencich/verilog-i2c (MIT license, single file, no dependencies). It is used UNMODIFIED;
    keep its license header and credit it in the report. Any adaptation goes in our own wrapper (ina226_reader.sv).
    Not used: Gowin's built-in I2C Master IP (register-based, harder to drive, Gowin-only) and the newer
    fpganinja/taxi library (large SystemVerilog library, CERN-OHL-S copyleft license).
- Fault source mapping (implemented):
    overvoltage / undervoltage -> INA226 bus voltage vs thresholds (fee.sv)
    overcurrent                -> INA226 current register vs threshold, both directions (fee.sv)
    overtemperature            -> DS18B20 temperature vs thresholds (fee.sv)
    sensor_failure             -> sensor_failure pin OR temperature_error OR measurement_error (reader errors)
    fan_failure, communication_timeout -> unchanged 1-bit inputs
  The old 1-bit overcurrent / overvoltage / undervoltage input pins were REMOVED (replaced by the INA226 path).
- Caveat noted: polled I2C/1-Wire readings are too slow for short-circuit protection (overcurrent reacts after
  INA226_READING_COUNT readings, about 3 x 4.7 ms = 14 ms). A faster RTL path using the INA226 ALERT pin is
  possible later (needs Mask/Enable + Alert Limit register writes in ina226_reader and 1 input pin); NOT done.
  Any other fast protection is the hardware team's job.

7. POWER-STATE FSM: fsm.sv (module power_state_machine)
--------------------------------------------------------
- Inputs: clk, reset_n (async, active-low), boot_success, mcu_heartbeat, battery_low, battery_critical,
  warning_request, shutdown_request, critical_request, manual_power, manual_shutdown, shutdown_success.
- Outputs: system_enable, warning_led, critical_clear, buzzer_alert, recovery_mode (all registered).
- All external inputs go through 2-stage synchronizers.
- States (one-hot, 7 bits): OFF, BOOT, NORMAL, WARNING, CRITICAL, SHUTDOWN, RECOVERY.
    OFF       -> BOOT on a rising edge of manual_power.
    BOOT      system_enable=1. -> NORMAL when MCU is alive (heartbeat seen) AND boot_success.
              -> OFF if boot timeout (10 s) expires.
    NORMAL    system_enable=1.
    WARNING   system_enable=1, warning_led=1. -> NORMAL when warning_trigger clears.
    CRITICAL  system_enable=0, warning_led=1, buzzer_alert=1. Retry with manual_power press if
              retry_count < 3: pulses critical_clear and goes to BOOT. retry_count only cleared by reset_n.
    SHUTDOWN  system_enable=1 until shutdown_success or shutdown timeout (10 s, then system_enable=0).
              Then -> RECOVERY if the shutdown was caused by battery_critical (battery_fault_latch), else -> OFF.
    RECOVERY  recovery_mode=1. -> BOOT when battery_critical clears.
- Global overrides (checked after the state case, in priority order):
    1. MCU heartbeat timeout (3 s placeholder, only after a heartbeat was seen) -> CRITICAL (from any state except OFF/CRITICAL)
    2. critical_trigger (= critical_request) -> CRITICAL (from NORMAL, WARNING, BOOT, SHUTDOWN)
    3. shutdown_trigger (= manual_shutdown | shutdown_request | battery_critical) -> SHUTDOWN (from NORMAL, WARNING)
    4. warning_trigger (= warning_request | battery_low) -> WARNING (from NORMAL)
- Heartbeat: any toggle of mcu_heartbeat = MCU alive. mcu_alive is cleared in OFF and on a CRITICAL retry.
- One reusable timer (29-bit) for boot/shutdown timeouts.
- Not part of the current refactor. battery_low / battery_critical could later come from INA226 bus voltage.


8. FAULT EVENT ENGINE: fee.sv (module fault_event_engine)
---------------------------------------------------------
Parameters:
  CLK_FREQ_HZ                  (no default, set by top level)
  OVERTEMP_SET_C        = 60   overtemperature trips at or above this (°C)
  OVERTEMP_CLEAR_C      = 55   overtemperature releases below this (°C)
  OVERTEMP_READING_COUNT = 3   consecutive readings over the limit before the fault is reported (1..255)
  OVERVOLTAGE_SET_MV    = 14_600, OVERVOLTAGE_CLEAR_MV  = 14_200   (placeholders, must match the battery)
  UNDERVOLTAGE_SET_MV   = 10_500, UNDERVOLTAGE_CLEAR_MV = 11_000   (placeholders, must match the battery)
  OVERCURRENT_SET_MA    = 5_000,  OVERCURRENT_CLEAR_MA  = 4_500    (placeholders, either current direction)
  CURRENT_LSB_UA        = 1000   must match ina226_reader (the top level passes the same value to both)
  INA226_READING_COUNT  = 3      consecutive INA226 readings beyond a limit before a voltage/current fault (1..255)
  Parameters have defaults so the top level does not have to pass them (config stays in fee.sv, but can
  be overridden per instance). The student prefers this over `define or packages.
Inputs:
  fan_failure, sensor_failure, communication_timeout  (1-bit, async, 2-stage synchronized, old style)
  bus_voltage [15:0] unsigned (1 LSB = 1.25 mV), current [15:0] signed (1 LSB = CURRENT_LSB_UA uA),
      measurement_valid (1-clock pulse), measurement_error (level)  (from ina226_reader, no synchronizer)
  temperature [15:0] signed (1 LSB = 1/16 °C), temperature_valid (1-clock pulse), temperature_error (level)
      (from ds18b20_reader, same clock, no synchronizer)
  critical_clear (from FSM)
Debounce (fault must persist before it becomes "valid"):
  counted in READINGS: overcurrent, overvoltage, undervoltage = INA226_READING_COUNT readings (~4.7 ms each),
                       overtemperature = OVERTEMP_READING_COUNT readings (~750 ms each)
  counted in clock cycles: sensor_failure 1 ms, fan_failure 10 ms, communication_timeout 30 ms
Voltage / current path (new): one comparator block updated on measurement_valid, same pattern as temperature:
  overvoltage_over_limit:  1 if bus_voltage >= set, 0 if < clear (levels = mV * 4 / 5)
  undervoltage_under_limit: 1 if bus_voltage <= set, 0 if > clear
  overcurrent_over_limit:  1 if current >= set OR current <= -set, 0 if -clear < current < clear
    (levels = mA * 1000 / CURRENT_LSB_UA; both directions because the sign depends on current direction)
  ina226_result_ready (1 clock after measurement_valid) drives the three reading-count debounce counters.
Overtemperature path (new):
  comparator block: on temperature_valid, over_limit=1 if temperature >= set level, =0 if < clear level,
  else keep (hysteresis). It also creates overtemperature_result_ready (1 clock after temperature_valid)
  so the debounce uses the freshly updated result. The debounce counter increments on each result_ready
  with over_limit=1 (saturates at the count) and resets to 0 on a reading below the limit.
sensor_failure path: debounced input is (sensor_failure_sync || temperature_error || measurement_error).
Responses:
  critical_response = latched (overcurrent | overvoltage); stays high until critical_clear from FSM.
  shutdown_response = overtemperature | sensor_failure   (registered)
  warning_response  = undervoltage | fan_failure | communication_timeout (registered)
Fault code bus / buzzer pattern (priority encoder, highest first):
  overcurrent           code 001  buzzer 11 (critical)
  overvoltage           code 010  buzzer 11 (critical)
  overtemperature       code 011  buzzer 10 (shutdown)
  sensor_failure        code 100  buzzer 10 (shutdown)
  undervoltage          code 101  buzzer 01 (warning)
  fan_failure           code 110  buzzer 01 (warning)
  communication_timeout code 111  buzzer 01 (warning)
  no fault              code 000  buzzer 00


9. DS18B20 READER: ds18b20_reader.sv (module ds18b20_reader)
------------------------------------------------------------
Parameters: CLK_FREQ_HZ (no default), CONVERSION_TIME_MS = 750 (DS18B20 worst case at 12-bit).
Ports: clk, reset_n, inout wire dq, temperature [15:0] signed (1/16 °C), temperature_valid (1-clock pulse
       per good reading), temperature_error (high while the last attempt failed, cleared by next good reading).
Pin driver: open-drain style, `assign dq = dq_drive_low ? 1'b0 : 1'bz;` (the line is pulled high by the hardware).
dq input goes through a 2-flop synchronizer (reset value 1 = idle line).
Structure:
  - Timing constants in us, converted to clock cycles (reset low 480 us, presence sample at 550 us, reset slot
    960 us, write-0 low 60 us, write-1 low 6 us, read low 6 us, read sample at 12 us, bit slot 70 us).
  - always_comb: slot timing for the current operation.
  - 1-Wire engine: one operation at a time (OP_RESET, OP_WRITE_BYTE, OP_READ_BYTE), LSB first,
    op_start / op_done handshake with the sequence FSM.
  - CRC-8 (x^8 + x^5 + x^4 + 1, Dallas/Maxim), updated per bit read.
  - Sequence FSM, repeating forever:
      SEQ_START (line must be high) -> SEQ_RESET_1 (presence check) -> SEQ_SKIP_ROM_1 (0xCC)
      -> SEQ_CONVERT_T (0x44) -> SEQ_WAIT_CONVERSION -> (line must be high) SEQ_RESET_2 -> SEQ_SKIP_ROM_2 (0xCC)
      -> SEQ_READ_SCRATCHPAD (0xBE) -> SEQ_READ_DATA (9 bytes) -> SEQ_CHECK_CRC -> SEQ_START
  - A reading is accepted only if CRC over all 9 bytes == 0 AND config byte (scratchpad byte 4) has its
    lowest 5 bits = 1. The config check rejects all-zero data from a line stuck low (all zeros passes CRC).
  - Errors (temperature_error = 1, old temperature kept): no presence pulse, line stuck low, CRC/config fail.
  - Single sensor on the line only (uses Skip ROM).
Known limitation: DS18B20 power-on value is 85 °C with a valid CRC. Could appear once after a sensor brownout;
the 3-reading debounce in the FEE filters a single such reading.
Verified in simulation (Icarus Verilog, model DS18B20 at 27 MHz): 25.0625 °C -> 401, -10.125 °C -> -162,
CRC error, missing sensor, line stuck low (also during byte reading), and recovery from each.


10. INA226 READER: ina226_reader.sv (module ina226_reader)
---------------------------------------------------------
Uses i2c_master.v (instance u_i2c_master) for all bit-level I2C timing.
Parameters (all with defaults):
  CLK_FREQ_HZ (no default), I2C_FREQ_HZ = 100_000, INA226_ADDRESS = 7'h40,
  SHUNT_RESISTANCE_MOHM = 10 (placeholder), CURRENT_LSB_UA = 1000 (1 mA per bit),
  CONFIG_VALUE = 16'h4127 (INA226 default: no averaging, 1.1 ms conversions, continuous shunt + bus),
  CONVERSION_TIME_US = 2500 (must be longer than one shunt + bus conversion; increase if averaging is changed).
Derived: CALIBRATION_VALUE = 5_120_000 / (CURRENT_LSB_UA * SHUNT_RESISTANCE_MOHM) (= 512 with defaults),
  I2C_PRESCALE = CLK_FREQ_HZ / (I2C_FREQ_HZ * 4) (= 67 at 27 MHz), timeout = conversion time + 20 ms.
Ports: clk, reset_n, inout wire scl, inout wire sda,
  bus_voltage [15:0] unsigned (1 LSB = 1.25 mV), current [15:0] signed (1 LSB = CURRENT_LSB_UA uA),
  measurement_valid (1-clock pulse when both values are new), measurement_error (high while last attempt failed).
Pins: open-drain, `assign sda = sda_o ? 1'bz : 1'b0;` (same for scl); scl/sda inputs through 2-flop synchronizers.
i2c_master.rst = !reset_n || i2c_reset (i2c_master uses an active-high synchronous reset).
Structure:
  - Transaction engine (TR_* states): one 16-bit register write (write_multiple: pointer, MSB, LSB, stop) or
    read (write pointer, repeated start, read MSB, read LSB + stop) through i2c_master's valid/ready streams.
    op_start / op_done / op_failed handshake; op_failed = latched i2c_master missed_ack (1-clock strobe).
  - Sequence FSM, repeating forever (~4.7 ms per measurement):
      SEQ_START -> SEQ_WRITE_CONFIG -> SEQ_WRITE_CALIBRATION -> SEQ_CHECK_CALIBRATION (read back, must match)
      -> SEQ_WAIT_CONVERSION -> SEQ_READ_BUS_VOLTAGE -> SEQ_READ_CURRENT -> SEQ_UPDATE_OUTPUTS -> SEQ_START
  - Config and calibration are rewritten EVERY cycle: if the INA226 resets it loses calibration and would
    report 0 A (overcurrent could never trip); rewriting self-heals, the read-back detects it.
  - The conversion wait guarantees every measurement_valid carries a FRESH conversion (so "N readings in a row"
    in the FEE never counts the same sample twice).
  - Timeout watchdog: if a measurement takes longer than conversion time + 20 ms (e.g. stuck line makes
    i2c_master wait forever), measurement_error = 1, i2c_master is reset, sequence restarts.
  - Errors (measurement_error = 1, old values kept): missed ACK, calibration read-back mismatch, timeout.
Verified in simulation (Icarus Verilog, behavioral INA226 I2C model, 27 MHz): 12 V / 2.5 A -> 9600 / 2500,
11 V / -1 A -> 8800 / -1000, calibration 512 written, INA226 missing, SDA stuck low, SCL stuck low,
calibration not kept -> error; recovery from each.
